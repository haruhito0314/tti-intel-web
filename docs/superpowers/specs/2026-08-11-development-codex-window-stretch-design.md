# Developmentページ Codexウィンドウ遷移設計

## 目的

`/development`冒頭のCodex起動場面を、別画面への差し替えや内容の消失に見えない自然な遷移へ変更する。同時に、Codex内の実装進行と右側の変更ファイル欄の表示時刻を一致させる。

## 現状の問題

- Codexウィンドウの拡張中、内部のタイトルバーとアプリ画面を透明化しているため、同じ画面を引き伸ばしているように見えない。
- ウィンドウの位置と大きさは連続的に変わるが、内部表示の消失と再表示が別の動きとして見える。
- 右側の変更ファイル用カラムは実装途中で先に確保され、変更ファイルの内容は後から表示されるため、空の領域が生じる。
- 実装計画の「3 / 3」、変更ファイル、Codexの完了メッセージが別々の時刻に切り替わり、作業の因果関係が弱い。

## 採用する見せ方

最初から表示されている一つのCodexウィンドウを、そのまま作業画面として使用する。ウィンドウのDOMや内部画面を差し替えず、外枠の位置・横幅・高さだけを連続的に変化させる。

拡張中もタイトルバー、サイドバー、スレッド、入力欄を表示し続ける。内部の透明化は行わない。文字やUIは現在のレイアウトを使って自然に再配置し、画面全体を画像のように拡大して文字がぼやける方法は採用しない。

## 起動モーション

1. 左側のCodexウィンドウ、右上のTerminal、右下のアプリ群を表示する。
2. カーソルがCodexウィンドウへ移動し、選択する。
3. 同じCodexウィンドウが内容を保ったまま横方向へ広がり、中央の作業位置へ移動する。
4. Terminalとアプリ群はCodexの移動開始後にフェードアウトする。
5. Codexウィンドウの拡張が完了してから入力欄へカーソルを移す。

位置・幅・高さは同じイージングと同じ継続時間を使う。途中で座標系を切り替えたり、`left`の移動と反対方向の`translate`を組み合わせたりしない。これにより、振動や一瞬の逆移動を防ぐ。

## 変更ファイルの時間軸

実装の進行は次の順番に統一する。

1. 実装計画の最後の項目を処理中として表示する。
2. 実装完了時刻に、計画を「3 / 3」へ更新する。
3. 同じ時刻に右側の変更ファイル欄を開き、`Home.tsx`を表示する。
4. 0.2秒後に`index.css`を追加する。
5. 両ファイルの表示後にCodexの完了メッセージを表示する。

右側のカラムを先に開いて空白を見せることはしない。カラム拡張と最初のファイル表示を同じ状態値から制御する。

## 実装方針

- 起動時刻、拡張完了時刻、実装完了時刻、2ファイル目の表示時刻をモーション用モジュールへ集約する。
- Codexウィンドウの内容表示状態を、拡張状態から切り離さない。
- `.is-review-visible`はステップ番号ではなく、最初の変更ファイルが利用可能になった状態で付与する。
- 計画の「3 / 3」と最後の項目の完了状態も同じ実装完了状態から算出する。
- 既存の一つのCodexウィンドウを維持し、新しいウィンドウを重ねて作らない。

## レスポンシブ対応

- PCでは左側のCodexウィンドウから中央へ自然に広げる。
- スマホでは同じ内容を維持するが、サイドバーと右側の変更ファイル欄は既存どおり非表示とし、本文内の変更ファイル表示を使う。
- 320px、360px、390px幅で横方向のはみ出しがないことを確認する。
- 拡張中に文字が重なる、画面が振動する、カーソルが対象から外れる状態がないことを確認する。

## テストと確認

- モーション用の時刻判定を単体テストし、実装完了・1ファイル目・2ファイル目・完了メッセージの順序を固定する。
- DOMテストでCodexウィンドウが一つだけであることを維持する。
- ブラウザで起動前、拡張中、拡張後、変更ファイル表示時を確認する。
- PCとスマホの両方で、ウィンドウ外へのはみ出しと文字の重なりを確認する。
- 対象テスト、Lint、型検査、本番ビルドを実行する。

## 対象外

- Codex画面の文章やデザイン全体の刷新
- Preview以降のVercel、AWS、Plugin、MCP場面の変更
- 再生時間全体の大幅な短縮・延長
- 新しい操作ボタンや再生コントローラーの追加
