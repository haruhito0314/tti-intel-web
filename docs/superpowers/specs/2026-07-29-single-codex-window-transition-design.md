# 同一Codexウィンドウ遷移 設計

## 目的

最初のワークスペースで表示しているCodexウィンドウを、そのまま中央へ移動・拡大して開発シーンへ接続する。別のCodexウィンドウへの差し替えやクロスフェードは行わず、利用者が「掴んだ同じ画面を使い続けている」と理解できる動きにする。

## 現状の問題

- 最初に表示する `.dx-launcher-codex-screen` と、操作シーンで表示する `.dx-product-window` が別要素になっている。
- 前者が消える前後で後者が表示されるため、同じウィンドウを移動したように見えない。
- 4.0〜4.2秒の切り替え区間ではカーソルの対象が `null` になり、カーソルが一度消える。

## 採用する構成

### 1. Codexウィンドウを一つに統合

Codex本体のDOMは一つだけにする。最初は左側の小さいウィンドウとして配置し、カーソル操作後に中央へ移動しながら拡大する。

移動完了後も同じ外枠、タイトルバー、ウィンドウ要素を保持する。コンパクト表示で省略していた内部情報だけを、ウィンドウの拡大に合わせて詳細表示へ切り替える。

### 2. 遷移の順序

1. Codex、Terminal、ランチャーを同時に表示する。
2. カーソルをCodexのタイトルバーへ移動する。
3. 押下状態を示し、Codexウィンドウを中央へ移動・拡大する。
4. 移動開始後にTerminalとランチャーをフェードアウトする。
5. Codexが中央に収まってから、内部の入力欄や会話内容を表示する。
6. 以降の入力、送信、実装、プレビュー表示も同じCodexウィンドウ内で続ける。

### 3. カーソル

- カーソルはシーン全体で一つだけ使用する。
- Codexの移動中はタイトルバー上の座標へ毎フレーム追従する。
- ウィンドウ切り替え用の非表示時間を廃止する。
- ウィンドウ、ガラス、説明カードより高い表示階層に固定する。
- クリック中だけ縮小し、クリック終了後も同じ位置から次の対象へ移動する。

## 実装境界

- `.dx-launcher-codex-screen` と `.dx-product-window` の重複を解消する。
- Terminalとアプリランチャーは補助要素として残し、Codexの移動開始後に消す。
- プレビューウィンドウは今回の変更対象外とする。
- PCとスマホの両方で、同一ウィンドウが画面およびガラス領域からはみ出さないようにする。

## CLI連携以降の実在性

Vercel・AWS・Plugin・MCPの各シーンでは、実際の製品に存在しない統合画面や操作を作らない。情報を見せるためだけの独自ダッシュボード、架空の「実行」ボタン、処理フロー図は廃止する。

### Vercel・AWS

- Codex CLIへ日本語で指示を送る。
- Codexが実行したVercel CLIまたはAWS CLIのコマンドと結果を、Codex CLIの会話内に表示する。
- 結果確認ではVercelまたはAWSの実在する管理画面を別ウィンドウとして表示する。
- Terminal、Vercel、AWSのウィンドウを切り替えるときは、カーソルで対象ウィンドウを選択する。

### Plugin

Pluginは実行対象として扱わない。Codex CLIで`/plugins`を開き、Pluginを選択、インストール、有効化する実際の流れを表示する。

インストール後は新しいCodexセッションへ戻り、通常の文章またはPluginに含まれるスキル名で指示を送る。現在の「実行」ボタン、架空の進捗一覧、Plugin専用Terminalは削除する。

### MCP

MCPは独立したアプリ画面として扱わない。Terminalで`codex mcp list`を実行して設定済みサーバーを確認し、その後のCodexセッションで接続済みMCPツールが呼ばれる流れを表示する。

現在の接続図、「接続して確認」ボタン、「3 connected」の架空画面は削除する。Browser UseはMCPと混同せず、必要な場合はCodexの別ツールとして表示する。

## 公式仕様との対応

- Pluginはスキル、MCPサーバー、または両方をまとめる配布単位であり、独立した実行アプリではない。
- Codex CLIでは`/plugins`からPluginを閲覧、インストール、有効化する。
- Pluginのインストール後は新しいセッションでスキルやツールを利用する。
- MCPサーバーは`codex mcp`コマンドで追加、一覧、認証、削除を管理する。

## 確認項目

- DOM上に主要なCodexウィンドウが一つだけ存在する。
- 移動前後で同じ要素の位置と大きさが変化している。
- 4.0〜4.2秒を含め、操作中にカーソルが消えない。
- カーソルがウィンドウやガラスの背面へ入らない。
- 390px、360px、PC幅でウィンドウが見切れない。
- 自動再生を繰り返しても同じ開始状態へ戻る。
- Pluginシーンに「実行」ボタンや架空の専用処理画面が存在しない。
- MCPシーンに独自の接続図や架空の接続ボタンが存在しない。
- CLI以降に表示する操作が、実際のCodex、Vercel、AWSの画面またはコマンドで説明できる。
