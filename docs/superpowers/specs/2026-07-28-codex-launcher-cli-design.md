# CodexランチャーとCLI連携の演出設計

## 目的

開発ページの冒頭で、複数のAI開発アプリからCodexを選ぶ操作を明確に見せる。続く公開・クラウド連携では、Terminal上のCodex CLIへ日本語で指示すると、必要なCLIコマンドが自動実行される因果関係を伝える。

## 冒頭の演出

1. 左に起動中のCodex、右上にTerminal、右下にアプリランチャーを正面向きで配置する。
2. 3画面は最初のフレームから正面を向き、角度変化を行わない。
3. アイスブルーのカーソルがランチャー内のCodexをクリックする。
4. 他の画面が後退し、Codex画面がガラス面全体へ広がる。
5. 既存のHome改修デモを開始する。

アプリはアイコンだけではなく、タイトルバーと画面内容の一部を持つ「起動中の小画面」として見せる。初期状態から互いに重ならず、スマホでも2×2を維持する。

## CLI連携の演出

公開・クラウド連携シーンの最初にTerminalを選ぶ。Terminal内で`codex`を入力してCodex CLIを起動し、次の日本語指示を入力する。

> VercelとAWSに連携して、このサイトを公開できる状態にして

Codex CLIは指示を理解した表示を出し、`vercel deploy --prod`を実行する。Vercel画面で公開完了を確認したあと、Terminalへ戻り、Codex CLIが`sam deploy --guided`を実行する。最後にAWS画面で構築完了を確認する。

## 速度

- 正面配置を約2.3秒見せてからCodexをクリック
- Codex画面の展開は約1秒
- CLI連携シーンは約14.5秒を使い、各選択画面を1.5秒以上見せる

## ガラスの役割

- Codex、Terminal、ランチャーを載せる大ガラスは、Codexを開く前後で位置・大きさ・角度を変えない。
- 起動時の拡大は大ガラス全体へ適用せず、Codex画面とカーソルだけで選択状態を伝える。
- 左下の説明カードは、参考画像に近い青紫の濃いガラスとする。背景光を強く通さず、白文字の可読性を優先する。
- 説明カードには細い明色の境界線と弱い内側ハイライトを付けるが、強い発光や背景連動の色変化は加えない。
- 公開・クラウド連携の3ウィンドウを載せる土台は白寄りの半透明ガラスとし、Terminal画面だけを暗色に保つ。
- Codex、Terminal、ランチャー、Vercel、AWS、CLI Terminalは、それぞれ独立した薄いアイスブルーのガラス板に載せる。
- 各ガラス板は白い境界線、弱い内側ハイライト、柔らかい影を持ち、アプリ本体の内容は不透明なまま保つ。
- Previewを開いた後も左下の最終説明を表示し、CodexとPreviewが次のシーンへ切り替わる直前にだけ説明を消す。

## 検証

- 開発ページに4アプリの名前と日本語のCLI指示が存在する
- TerminalにCodex CLI起動、Vercel実行、AWS実行が存在する
- ビルド、ESLint、Developmentページのテストが通る
- PCとスマホで4画面が重ならないCSS配置になっている
- Codex起動中も大ガラスの矩形が動かない
- 説明カードの背景が十分に濃く、背後の光で文字が読みにくくならない
- 6画面すべてに個別のガラス板が存在する
- Preview表示後もCodexの最終説明が残る
