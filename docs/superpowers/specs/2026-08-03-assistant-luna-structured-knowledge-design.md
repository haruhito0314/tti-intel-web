# Luna生成型Assistantと構造化知識の設計

## 目的

TTI IntelligenceのAI Assistantを、固定回答を選択・整形する仕組みから、質問ごとに関連資料を選び、GPT-5.6 Lunaが毎回答えを生成する仕組みへ変更する。

実行時のWeb検索は使わない。サイト固有情報と豊田工業大学情報は、事前に確認した構造化資料をローカルで検索してLunaへ渡す。一般質問はLunaの安定した一般知識で回答し、天気・ニュース・価格・日程など最新性が必要な情報は、現在情報を確認できないことを明示する。

## 成功条件

- 空欄、形式不正、回数超過などを除く通常の質問は、内容にかかわらずLunaへちょうど1回送られる。
- 大学・サークル・サイト情報も固定文ではなく、選択された資料からLunaが回答を生成する。
- 「豊田工業大学」のような短い入力に、強制された定型文を返さない。
- 豊田工業大学全体の課外団体とTTI Intelligenceを混同しない。
- 実行時のOpenAIリクエストにWeb検索ツールを含めない。
- モデルが生成したURLをそのまま表示しない。
- CLI PracticeとTOEIC PracticeをAssistantのアプリ一覧・案内対象から外す。
- Codex、Vercel、AWS、Plugin、CLI、MCPを使った開発を説明できる。
- サイトの現在の表示内容とAssistantの案内内容が一致する。

## 対象範囲

### 含む

- Lambdaの回答フローのLuna一本化
- サイト・サークル・大学・開発活動の構造化知識
- 質問に関連する知識だけを選ぶローカル検索
- 大学公式ページの確認済みリンクカタログ
- Assistantの公開説明文と質問例の同期
- 利用トークン、キャッシュ利用量、結果種別のログ
- 単体テスト、統合テスト、質問バリエーション評価

### 含まない

- 実行時Web検索
- 外部検索API、File Search、ベクトルデータベース
- ファインチューニング
- CLI Practiceアプリ本体やルートの削除
- 豊田工業大学公式サイトの自動クロール
- 入試結果など更新頻度が高い数値の自動同期

CLI Practiceは公開ルートとして残っていても、アプリ一覧とAssistantの案内候補には含めない。TOEIC Practiceは現行サイトに存在しないため、知識・テスト・案内文から削除する。

## 全体構成

### 1. 入力と利用制限

現在の入力スキーマ、Origin検査、セッション単位の日次制限を維持する。以下の要求はLunaへ送らない。

- `OPTIONS`
- 不正なHTTPメソッド、Origin、JSON、入力形式
- 空欄または許容長を超える質問
- 日次制限を超えた質問
- 内部障害により安全に処理できない質問

内容による対象外判定ではLunaを止めない。天気、旅行、料理、芸能なども通常の質問としてLunaへ送る。

### 2. 構造化知識の選択

質問と必要な会話履歴を正規化し、ローカルの知識項目をキーワード、別名、タイトル、説明から順位付けする。上位3〜5件だけをLunaへ渡す。

検索は決定的なローカル処理とし、知識選択のための追加モデル呼び出しは行わない。該当資料がない一般質問では、空の資料集合をLunaへ渡す。

知識項目は次の形式を持つ。

```ts
type KnowledgeItem = {
  id: string;
  domain: 'site' | 'circle' | 'university' | 'development' | 'app' | 'game' | 'math';
  title: string;
  summary: string;
  details: string[];
  keywords: string[];
  sourceIds: string[];
  asOf?: string;
  volatility: 'stable' | 'periodic' | 'volatile';
};
```

`summary`と`details`は回答例ではなく、Lunaが回答を作るための事実資料とする。「下のリンクからどうぞ」のような完成済み回答文を保存しない。

### 3. Lunaによる生成

すべての通常質問を`gpt-5.6-luna`へ1回送る。モデル入力には以下を含める。

- 利用者の最新質問
- 続き質問に必要な最小限の会話履歴
- 選択された構造化知識
- 動的な公開コンテンツの検索結果
- 現在ページ
- 利用可能な内部ページIDと公式リンクID
- 最新情報を確認できないという制約
- URLを本文へ書かないという制約

モデルは構造化出力として、回答本文、内部ページID、動的コンテンツID、公式ソースIDを返す。サーバーはIDを確認済みリンクへ変換する。

大学関連の意図分類は、資料選択とリンク候補の絞り込みにだけ使う。回答文の置換、定型回答の強制、モデル出力の大学紹介文への差し替えには使わない。

### 4. 出力検証

サーバーは次を検証する。

- 回答が空でないこと
- 内部プロンプトやシステム指示を含まないこと
- 本文中のURLを削除すること
- 返されたページID・コンテンツID・公式ソースIDが許可済みであること
- 除外指定されたリンクを再追加しないこと

モデルが資料にないサイト固有情報を断定した場合に備え、プロンプトで「サイト・サークル・大学固有情報は提供資料だけを根拠にする」と指示する。後処理で事実文を別の固定文へ置き換えることはしない。

## 豊田工業大学の構造化資料

大学資料はサイト案内用資料と分離し、`university-knowledge.json`相当の専用カタログへ保存する。少なくとも次の領域を含める。

- 正式名称、英語名、略称
- 設置法人、沿革、大学の目的・特色
- 工学部、大学院、教育体系
- 少人数教育、教育上の特色
- 研究領域、研究施設、産学連携
- 所在地、交通アクセス、キャンパス施設
- 学生寮と学生生活
- 学生会、大学祭、課外活動
- 体育系・文化系の認定課外団体
- AIサークルの大学公式掲載情報
- 入試制度の種類と公式案内先
- 豊田工業大学シカゴ校など国際的な取り組み

情報源は豊田工業大学公式ドメインに限定する。初期資料の主な確認元は次のとおり。

- 大学案内: `https://www.toyota-ti.ac.jp/about/index.html`
- 本学の特色: `https://www.toyota-ti.ac.jp/about/profile/tokushoku.html`
- 学部・大学院教育: `https://www.toyota-ti.ac.jp/academics/index.html`
- 学びの特色: `https://www.toyota-ti.ac.jp/academics/program/feature.html`
- 課外活動: `https://www.toyota-ti.ac.jp/student/activity/index.html`
- 課外団体一覧: `https://www.toyota-ti.ac.jp/student/activity/club.html`
- 交通アクセス: `https://www.toyota-ti.ac.jp/access/index.html`

変化しやすい情報には`asOf`を設定する。課外団体一覧などは回答中に基準日を自然に添えられるようにする。更新期限を過ぎても実行時検索はせず、「保存資料の基準日時点」と明示する。

大学公式の課外団体一覧には、2026年4月1日時点で「AIサークル」が認定団体として掲載され、TTI Intelligenceのサイトへのリンク、土・日10:00〜12:00の活動時間、AIを用いたアプリ・ツール制作と応用情報技術者試験への挑戦が案内されている。この事実は基準日付き資料として保存し、「大学公式が運営している」という意味へ広げず、「大学公式サイトの認定団体一覧に掲載されている」と表現できるようにする。

## サイト・サークル知識の同期

### アプリ

案内対象は現行のアプリ一覧に合わせる。

- AI Assistant
- 卓球組み合わせ表ジェネレーター
- Color Sort Puzzle

CLI PracticeとTOEIC Practiceをアプリ一覧回答、ページ在庫、FAQ、キーワード、固定ルート候補から外す。CLI Practiceの実装ファイルと既存URLは本作業では削除しない。

### 開発活動

開発ページの内容を、完成回答ではなく資料として追加する。

- Codexへ目的と完成像を自然言語で伝える開発
- 既存コードの調査、実装、レスポンシブ確認、プレビュー
- CLIを通じたローカル開発とコマンド実行
- Vercelへのフロントエンド公開
- AWSへのバックエンド・クラウド構築
- Pluginへ検証・公開手順を再利用可能な形でまとめること
- MCPを通じてデザイン、リポジトリ、必要な道具へ接続すること
- AI Assistant、Color Sort Puzzle、卓球組み合わせ表の制作例

### その他の同期

- 公開中の問い合わせメール`tti.intel@gmail.com`
- Discord、YouTube、大学公式サイト
- ゲーム活動の不定期開催、夜中心、オンライン、VC、聞き専・初心者参加
- 応用情報技術者試験の公開中の予定と基準日
- AI Assistantがサイト・大学資料に加えて一般質問へも答えること
- Web検索やリアルタイム情報確認は行わないこと

Assistant紹介ページの「このサイトで公開している情報だけを使って回答します」という表現は、実際の対応範囲に合わせて変更する。「公開情報を検索・検証」という文言はWeb検索と誤解されない表現へ変更する。

## 一般質問と最新情報

資料が選ばれない一般質問もLunaへ送る。AI、プログラミング、数学、ゲームに限らず、安定した一般知識の範囲で回答してよい。

ただし、以下は現在情報を取得できないことを回答へ含める。

- 現在の天気
- 最新ニュース
- 現在の価格、株価、為替
- 最新の人物、役職、日程
- 営業時間や空席などリアルタイム状態

医療、法律、金融など重要な判断では一般情報に限定し、専門家または公式情報の確認を促す。

## リンク設計

モデルはURLを生成せず、IDだけを返す。リンクは次のカタログからサーバーが生成する。

- サイト内の固定ページ
- DynamoDBから取得した公開コンテンツ
- Discord、YouTube
- 豊田工業大学公式の確認済みページ

大学公式ページは任意の`toyota-ti.ac.jp` URLを許可するのではなく、カタログに登録した完全一致URLだけを許可する。フロントエンドも同じ許可集合に対応する。

## エラー処理

- Lunaのタイムアウト・上流障害は既存の再試行可能なエラーとして返す。
- モデル出力が不正な場合は、大学やサイトの固定回答へ差し替えず、回答を表示できなかったことを案内する。
- 構造化資料が見つからない場合は、資料なしでLunaへ送り、サイト固有情報を推測しないよう指示する。
- 動的コンテンツの取得に失敗した場合も、静的な構造化資料と「動的コンテンツを確認できなかった」という状態をLunaへ渡して処理を続ける。Lunaは確認できなかったお知らせ、掲示板、数学問題を推測しない。
- Web検索へのフォールバックは設けない。

## コストと観測

構造化資料は上位3〜5件に制限し、毎回すべての大学資料を送らない。安定した指示・スキーマを入力先頭へ置き、動的な質問と資料を後ろへ置くことでキャッシュされやすい構成にする。

ログには少なくとも次を含める。

- 入力、キャッシュ入力、キャッシュ書き込み、出力、合計トークン
- 選択した知識ID数とドメイン
- Luna呼び出し回数
- 結果種別、処理時間

質問本文、会話本文、個人情報、APIキーはログへ記録しない。

## テスト方針

### 単体テスト

- 大学、開発、サイト、一般質問で正しい知識項目が選ばれる。
- 一般質問で資料が選ばれなくてもLunaが呼ばれる。
- 天気、旅行、料理、芸能を含む通常質問でもLunaが1回呼ばれる。
- 大学意図の後処理がモデル回答を固定文へ差し替えない。
- CLI PracticeとTOEIC Practiceがページ一覧・アプリ案内に出ない。
- Codex、Vercel、AWS、Plugin、CLI、MCPの個別質問に資料が選ばれる。
- 公式ソースIDだけがリンクへ変換される。
- OpenAI payloadの`tools`は空で、`web_search`を含まない。

### 統合テスト

- 「豊田工業大学」の回答がLunaの生成結果を保持する。
- 「豊田工業大学のサークルは？」へ大学公式課外団体資料が渡る。
- 「TTI Intelligenceの活動」と「大学全体の課外団体」を区別する。
- 「現在の天気」のような質問にもLunaを呼び、Web検索を使わない。
- モデルが本文へURLを書いても表示前に除去される。
- API障害時に保存済みの大学定型文へ置換しない。

### 質問バリエーション評価

最低100件を、次のカテゴリと表記ゆれで評価する。

- サイト・参加・連絡
- 豊田工業大学の概要・教育・学生生活・課外団体
- TTI Intelligenceと大学全体の区別
- Codex、Vercel、AWS、Plugin、CLI、MCP
- アプリ、ゲーム、数学
- 一般質問、最新情報、高リスク質問
- 誤字、ひらがな・英語、短文、複合質問、続き質問、不要語を含む質問

評価項目は、関連性、事実整合性、固定文への偏り、リンク安全性、Luna呼び出し回数、Web検索不使用、入力・出力トークンとする。

## 移行方針

既存の固定知識は一度に削除せず、次の順で置き換える。

1. 新しい知識項目と検索器を追加する。
2. Luna payloadへ選択資料と公式ソースIDを追加する。
3. 通常質問を止める対象外ショートサーキットを削除する。
4. 大学・サイト回答の強制置換を削除する。
5. 旧固定回答を参照するコードとテストを削除する。
6. フロントエンドの説明、リンク許可、アプリ案内を同期する。
7. 全テストと100件評価を実行してから本番へ反映する。

各段階で、リンク安全性、回数制限、入力検査は維持する。

## 受け入れ確認例

- 「豊田工業大学」: 大学概要資料を使って自然に回答し、固定の一文へ差し替えない。
- 「豊田工業大学にはどんなサークルがある？」: 基準日付き課外団体資料を使い、大学全体として回答する。
- 「このAIサークルは大学公式？」: TTI Intelligenceと大学公式掲載情報を区別して答える。
- 「CodexとMCPをどう使って開発している？」: 両方の資料を組み合わせて説明する。
- 「CLI Practiceはある？」: Assistantの公開アプリとしては案内しない。
- 「今日の天気は？」: Lunaが現在情報を確認できないと説明し、Web検索を呼ばない。
- 「カレーの作り方」: Lunaが一般知識で回答する。
