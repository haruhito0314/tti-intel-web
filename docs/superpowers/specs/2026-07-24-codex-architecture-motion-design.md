# Codex操作とSystem Architecture同期演出 — デザイン仕様

## 目的

`/development` のヒーロー内で、Codexアプリの操作とAI開発ワークフローの説明を一つの連続した体験として見せる。装飾目的のアニメーションではなく、利用者の操作がどの処理段階につながるかを視覚的に説明する。

表示するSystem ArchitectureはCodex内部の非公開構造を示すものではない。公開可能な情報だけを用いた、AIを使う開発ワークフローの概念図として扱う。

## ビジュアル方針

- Codex画面は明るいフロストガラスにし、白基調を保ちながら背後の構造がわずかに透ける。
- System Architectureは青みのある透明アクリルとして、Codex画面と素材を分ける。
- カーソルは半透明の白を基調に、水色から紫へ変化する輪郭と柔らかな発光を使う。黒い輪郭と暗いドロップシャドウは使わない。
- 透明度は均一にせず、文字、境界、操作対象のコントラストを優先する。

## 演出シーケンス

### 1. Instruction Layer

カーソルが入力欄へ移動し、指示を入力する。入力欄の背後に `Instruction Layer` が現れ、ユーザーの指示が処理の起点であることを示す。

### 2. Repository Context

送信操作の後、Codexのプロジェクト一覧と対象ファイルが反応する。光が `Repository Context` へ移動し、必要なコードと文脈を読み込む段階を説明する。

### 3. Model & Tool Execution

Codex画面に計画と処理中の状態が表示される。同時に `Model & Tool Execution` が展開し、前段から受け取った情報が処理へ渡る。

### 4. Patch & Review

画面内にDiffが現れたタイミングで `Patch & Review` を強調する。変更箇所とレビュー領域を半透明の光線で対応付ける。

### 5. Verification

カーソルがテストを実行し、成功結果が表示される。光が `Verification` まで到達し、最後に5段階の構成図全体が一枚の図として完成する。

## 画面遷移

Codex画面とSystem Architectureを別セクションへ切り替えない。操作の進行に合わせてCodex画面の一部が徐々に透明になり、背後の該当ノードだけが現れる。最終状態では操作画面と構成図が重なり、画面上の出来事とワークフローの対応関係を同時に確認できる。

## レスポンシブ設計

- デスクトップではCodex画面の背後と左右にArchitectureノードを展開する。
- 横幅が狭い画面ではノードを画面下部の一列タイムラインへ変換する。
- 高さが低い画面では説明文を一行へ短縮し、Codex画面をビューポート内に維持する。
- カーソル演出は細かいポインターが利用できる環境だけで表示する。

## アクセシビリティ

- `prefers-reduced-motion: reduce` では移動アニメーションを止め、5段階を静的に表示する。
- 色だけに依存せず、段階番号、見出し、接続線で状態を伝える。
- 半透明背景上でも本文と重要ラベルのコントラストを維持する。

## 検証条件

- 入力、送信、コンテキスト取得、Diff表示、テスト成功の各画面状態に、対応するArchitectureノードが一つだけ強調される。
- 最終状態で5段階すべてが表示され、接続順が明確である。
- カーソルの輪郭に黒または濃紺を使用しない。
- 390×844、844×390、1280×720でCodex画面、カーソル、Architectureがビューポートからはみ出さない。
- モーション軽減設定でも情報が欠落しない。

## 対象外

- OpenAIまたはCodexの非公開内部アーキテクチャの再現
- 実際のリポジトリや機密データとの接続
- デモ段階でのバックエンド処理
